# 0.5.3 账号检查修复记录

2026-09-12，Windows x64 开发验证版本。客户业务代码独立实现，既有 UI 许可继续保留。本轮没有新增依赖、云端服务或计费项目。

## 用户操作

1. 打开经营账号，进入本人账号详情。
2. 点击“检查并同步（不会发送）”。软件恢复已保存会话，核验本人身份，再依次读取商品、消息和可核验订单。
3. 查看各项真实结果，也可对单项再次检查。需要手机验证或重新登录时按具体提示处理。
4. 核对资料与规则后，另行决定是否开启托管。检查本身不会发送、发货、改价或退款。

新扫码账号确认绑定后自动进行相同的只读检查。重启后的“待检查”表示尚未恢复并核验会话，不代表会话已过期。尚未接入的软件功能单独说明；反复扫码不会开启它们。

## 实验目标与停止条件

假设：保存的本人会话仍有效，当前阻断来自本地恢复流程与返回结构处理。结果用于决定是否修复恢复路径、连接等待和商品解析，而不是要求用户重新扫码。

范围：检查身份、当前消息连接、商品列表、消息历史和可核验订单。遇到平台验证、拒绝、不兼容或需要发送时停止相关方向；不启用托管，不进行真实发布、修改、回复、发货或退款。没有通过耗尽额度、重复发送或故障操作验证真实订单。

## 本地测试

148 项测试通过，覆盖原有授权、库存预留、未知交付状态与权限边界。本次增加有效会话在暂停托管时只读恢复、无权限不恢复、恢复中暂停防止迟到结果、损坏会话不覆盖原保存文件、商品字符串末页标记、状态入口与内容转义，以及重启状态恢复检查。

宽窗口和 960 × 700 窗口检查通过：三项读取入口、发送连接与送达验证区分、未实现功能可展开、无整页横向溢出或未捕获页面错误。四行状态列表不再显示排序和分页。

## 本人账号的真实只读验证

使用一个已由本人扫码绑定的真实账号和原本机资料。保存会话成功恢复；身份与消息连接核验通过，未要求重新扫码。成功读取 13 件商品；消息读取一轮返回 64 条，去重后本机保留 30 个会话、168 条历史消息。该轮另跳过 33 条非文本或无法验证的记录，界面明确显示只读取了部分内容。

订单检查未取得可逐笔核验的订单，官网卖出订单入口当前要求在闲鱼 App 查看。这里的零条同步结果不代表平台没有订单，也不能据此刷新旧订单的付款或退款核验时间。

检查期间托管保持关闭，没有提交发送、交付、平台发货、修改商品或退款操作，没有新增交付记录。消息连接就绪只证明连接状态；实际消息送达与业务写入没有进行真实测试。原永久设备授权仍有效。

更正旧记录的边界：0.5.2 安装后曾观察到“需重新登录”，该状态不能证明保存会话失效；本次实际恢复证明至少本机此账号会话有效。
