# 0.5.4 安全增强与边界

目标是提高官方程序被修改、重打包和授权误用的成本。攻击者有公开源码、本机管理员权限和合法授权时，仍可重编译移除检查，或重新实现业务；不能宣称不可破解。已经公开的逻辑无法通过后续加壳收回。本次不改变仓库可见性、许可、离线约定或套餐权益。

| 风险 | 本次措施 | 兼容影响 | 验证方法 |
| --- | --- | --- | --- |
| 授权/设备响应被替换或结构畸形 | 严格 v1 JSON、设备身份、签名格式、期限与恢复结果核对 | 合法 v1 签名字节不变；畸形旧状态可能需要恢复原授权 | 合成篡改/错设备/恢复；本机永久授权只读检查 |
| 无限调用设备签名 | JS 与 C# 限定准备、本机状态、许可票据和报告会话用途与大小 | 原流程和报告新挑战兼容；拒绝非约定签名输入 | 纯 C# 用途向量与 JS 校验；不改变原密钥或 ACL |
| 调试或关闭隔离参数影响官方客户端 | 官方包危险参数下停止新经营动作，保留诊断和维护 | 开发模式保留调试；不会杀进程 | 隔离包和业务门禁分别验证，CDP 端口不保证关闭 |
| IPC 非主页面/已销毁页面请求 | 精确主窗口、主帧、地址和存活状态检查 | 不扩展页面权限 | 非法来源与销毁帧测试 |
| 商品操作缺少提交前权限复核 | 传递提交前回调，区分未提交拦截与结果未知 | 未来适配器仍须实际执行回调；不代表发布能力已接通 | 合成任务撤权、网络断开和无回执场景 |
| 应用归档、外置文件或构建输入被混入 | 归档完整性、Fuses、外置组件摘要和固定运行时文件清单 | 不关闭沙箱；保留原 Cookie 加密状态，拒绝未知构建材料 | 最小包篡改与最终包摘要校验 |
| 更新替换和本地回退 | 更新清单/文件摘要核验及本地观察版本约束 | 管理员完整回滚本机状态仍无法可靠防止 | 合成更新替换、取消及损坏元数据 |

商业保护器仅建立可替换的构建接入位置，当前未安装、采购或启用。AxProtector JavaScript、原生模块结合 VMProtect 等路线须另核实确切运行时支持、许可与发行权利、性能及维护成本，不能只保护 Electron 外壳就称业务源码已受保护。

TPM 不可导出密钥不等于程序未被修改。当前没有服务端 EK 证书链硬件证明，也没有不可回滚离线计数器；完整旧磁盘状态与时钟恢复仍有残余风险。未默认增加周期联网或云端经营核心。

发现异常时停止受影响的新动作，保留用户资料、未知交付和已提交回执；不销毁、不强制卸载、不关闭其他程序。ASAR 被破坏导致程序无法启动时，需要可信完整安装包修复，无法保证由已经损坏的程序展示修复页面。

未具备 Windows 商业发布者签名，仍为开发验证版本。发布者签名用于核验来源，并不保证所有 Windows 自动拒绝修改版。没有独立专业逆向评估证据。

安全改造来自本轮独立审计副本，经主任务逐项合入；本机回归、最小隔离包、真实 TPM 只读检查和最终安装后的证据必须分别记录。详见本次交付的安全审计与最终验证材料。
